# Отладка игр БК через MCP-сервер

Как гонять и разбирать игру, не открывая GUI: `./build/bk0010-emulator --server`
(регистрация в Claude Code — `.mcp.json`, сервер `bk0010`). Полный список
инструментов — в [README](../README.md#mcp-сервер-отладка-через-claude); здесь —
рецепты, проверенные на играх из корня репозитория.

> **Восьмеричное — в кавычках.** Голое JSON-число разбирается как ДЕСЯТИЧНОЕ:
> `{"code":12}` даст `000014` (СБР), а не `000012` (ВВОД). Пишите `"012"` или,
> лучше, `{"key":"enter"}`. Для адресов та же схема: `"014422"`, `0x18AB`, `6418`.

---

## 1. Загрузить игру и увидеть экран

```jsonc
bk_load       {"path": "KLAD2.BIN", "frames": 150}   // грузит монитор, .BIN, прогоняет 150 кадров
bk_screenshot {}                                      // PNG прямо в ответе
bk_vram       {"width": 128}                          // или ASCII-арт, если PNG не нужен
```

`frames` в `bk_load` экономит круг запрос/ответ. Отчёт печатает **фактическую**
точку входа: у образов ниже `01000` она выбирается эвристикой автостарта и не
совпадает с адресом загрузки.

Загружая **вторую** игру в той же сессии, ставьте `{"reset": true}` — иначе
`bk_hotspots`/`bk_coverage`/`bk_xrefs` смешают трассы двух программ.

**Сначала посмотрите на экран, потом жмите клавиши.** Почти все игры стартуют с
заставки, где ЦП крутится в ПЗУ (`PC=101120` — цикл опроса клавиатуры монитора), и
какая клавиша её снимает — предмет разведки. Клад-2: ВВОД → инструкция → ПРОБЕЛ →
выбор скорости `1`. Digger: меню, цифра выделяет пункт, ВВОД подтверждает.

## 2. Клавиатура

```jsonc
bk_key {"key": "enter"}                 // тап: защёлкнуть код, кадры не гонять
bk_key {"key": "right", "frames": 40}   // нажать, прогнать 40 кадров, отпустить
bk_key {"key": "right", "hold": true}   // удерживать; отпустить: {"hold": false}
bk_type {"text": "Привет\n"}            // строка, РУС/ЛАТ вставляются сами
```

Имена: `enter ввод space пробел left right up down tab backspace/заб home/вс
delete/сбр f1..f6 повт кт инд су рус лат`, либо один символ (`"1"`, `"A"`, `"ю"`).

**Почему `frames` важен.** Многие игры (Digger, PITON) читают не регистр кода, а
бит 6 регистра `0177716` — «клавиша физически нажата». Тап такую игру не сдвинет:
код защёлкнется, но удержания не будет. Проверка на Digger: из одной и той же
позиции `{"key":"right"}` + `bk_run 60` не двигает копателя, а
`{"key":"right","frames":60}` — двигает.

`bk_io_state` показывает и то, и другое: `data 0177662` с расшифровкой кода и
`System 0177716 (key-held bit6=0(down) — УДЕРЖИВАЕТСЯ)`.

## 3. Джойстик (параллельный порт 0177714)

Раскладка **липкая** — задаётся один раз и действует на все последующие вызовы и
на вывод `bk_io_state`:

```jsonc
bk_joystick {"layout": "klad2", "buttons": "right", "frames": 20}
bk_joystick {"buttons": "up+fire1"}          // выставить и оставить (липко)
bk_joystick {"release": true}                // отпустить всё
bk_joystick {"bits": "02000"}                // сырое значение порта
```

Раскладки: `standard` (Джойвокс/gid, по умолчанию), `breakhouse`, `swcorp`,
`klad2` — таблица битов в [`docs/joystick.md`](joystick.md), исходник —
`src/core/Joystick.h`. Кнопки: `up down left right fire1..fire5 button5` и русские
`вверх вниз влево вправо огонь`; `bit0`..`bit15` — сырой бит вне раскладки.

**Значение липкое по умолчанию** (как физически удерживаемый стик): игра
опрашивает порт раз в СВОЙ игровой кадр, который длиннее кадра 50 Гц, и
авто-отпускание «между опросами» дало бы немой отрицательный результат. `frames`
включает авто-отпускание после прогона, `hold: true` его отменяет.

Проверка сквозной цепочки на Клад-2 (координата игрока — `014422`):

```jsonc
bk_read_mem  {"addr": "014422", "len": 4}                                 // 017240
bk_joystick  {"layout": "klad2", "buttons": "right", "frames": 20}
bk_read_mem  {"addr": "014422", "len": 4}                                 // 017242 = +2
```

## 4. Сценарий ввода за один вызов

Когда нужна воспроизводимая последовательность управления, не гоняйте по вызову
на действие — опишите её таймлайном (`frame` — от начала этого прогона):

```jsonc
bk_run {"max_frames": 120, "input": [
  {"frame": 0,  "joy": "right"},
  {"frame": 25, "joy": "right+fire1"},
  {"frame": 60, "release_joy": true},
  {"frame": 62, "key": "enter"},
  {"frame": 70, "release_key": true}
]}
```

Тот же `input` принимает `bk_audio` — удобно записать звук ровно того действия,
которое его вызывает.

## 5. Кто и откуда читает порт / клавиатуру

Опрос устройства — это **чтение**, поэтому обычный лог записей его не видит:

```jsonc
bk_io_log {"enable": true, "reads": true, "addr": "0177714", "cap": 64}
bk_run    {"max_frames": 30, "input": [{"frame": 0, "joy": "up"}]}
bk_io_log {"count": 5}
//   R 177714 = 000004   port(джойстик)   PC=004720  MOV   @#177714, R3
```

`PC` — адрес самой инструкции доступа (а не «уехавший» вперёд регистр PC), так что
его сразу можно ставить в `bk_break`/`bk_xrefs`/`bk_callers`.

Альтернатива для одноразовой поимки — точка наблюдения: `bk_watch {"addr":
"0177714", "mode": "read"}`, затем `bk_run`. Хук доступа работает и на странице
В-В, так что это ловит опрос джойстика ровно на инструкции.

## 6. Определить раскладку джойстика неизвестной игры

```jsonc
bk_joy_probe {"bits": 6, "frames": 12, "start": "014400", "end": "014440"}
//   бит0  (000001): 014422:+2 014426:+2
//   бит1  (000002): 014420:+2
```

Для каждого бита: чекпоинт → выставить бит → прогнать → снять ОЗУ → сравнить с
опорным прогоном **без** ввода (чтобы отсеять таймеры и анимацию) → откатиться.
Малая ±дельта обычно горизонталь, большая — вертикаль (шаг строки экрана).
Состояние машины восстанавливается. Ручная процедура описана в
[`docs/joystick.md`](joystick.md#как-определить-раскладку-конкретной-игры).

## 7. Найти переменную, которую меняет ввод

```jsonc
bk_diff_mem {"action": "save"}
bk_joystick {"buttons": "up", "frames": 10}
bk_diff_mem {"action": "diff", "start": "014000", "end": "015000"}
```

Полезно в паре с чекпоинтами в памяти — они не трогают диск:

```jsonc
bk_state_save {"slot": "ingame"}    // сохранить позицию
… эксперимент …
bk_state_load {"slot": "ingame"}    // откатиться и попробовать иначе
```

Снимок теперь включает состояние джойстика и удержания клавиши, так что
«удерживаю вправо» переживает откат.

## 8. Звук

```jsonc
bk_audio {"frames": 60, "input": [{"frame": 2, "key": "1"}]}
```

Возвращает:

* WAV inline (блок `type:"audio"`), если клиент говорит на протоколе `2025-03-26`
  и новее; `{"inline": false}` выключает, `{"path": "x.wav"}` пишет на диск;
* пик / RMS / долю «не тишины» и ASCII-огибающую по окнам;
* **разбор на тоны** — частота и длительность каждого сегмента, посчитанные по
  фронтам бита 6 регистра `0177716` (точно, а не гаданием по нулевым пересечениям
  PCM): `40.2 мс: 1228 Гц, 11.4 мс`;
* `{"raw_start_ms": 40, "raw_ms": 5}` — дамп сырых int16-сэмплов окном.

`{"run": false}` не гоняет кадры, а просто забирает то, что уже лежит в FIFO
динамика (около 250 мс) — если звук уже прозвучал во время `bk_run`.

## 9. Разглядеть спрайт по пикселям

```jsonc
bk_vram {"mode": "index", "x": 16, "y": 100, "w": 48, "h": 12}
//  ........................................22.22222
//  ........................................32.23232
```

Режим `index` читает ВОЗУ напрямую (`0040000`, 64 байта на строку) и печатает
индекс палитры 0-3 на каждый пиксель БК — без скролла и без удвоения пикселей до
512, то есть ровно то, что лежит в памяти. Режим по умолчанию (`ascii`) — вид
всего экрана по яркости плюс счётчик непустых пикселей и bbox.
