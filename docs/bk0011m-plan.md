## 2. Железо БК-0011М — что именно эмулируем

### 2.1 Карта памяти

| Адреса | Содержимое |
|---|---|
| 000000–037777 | ОЗУ, страница 0 — всегда |
| 040000–077777 | **Окно 0**: любая ОЗУ-страница 0–7 |
| 100000–137777 | **Окно 1**: любая ОЗУ-страница 0–7 **или** ПЗУ-страница 0–3 |
| 140000–157777 | БОС, ПЗУ 324 — фиксировано |
| 160000–177577 | ПЗУ КНГМД (`disk326.rom`, 4 КБ) **или** МСТД (ПЗУ 330, 8 КБ) |
| 177600–177777 | Регистры |

- 128 КБ = 8 страниц × 16 КБ; физически страница N лежит по смещению `N*040000`.
- Роли страниц: 0 — фиксированная; 1–4 свободные; **5 — экранный буфер 0; 6 — экранный буфер 1**;
  7 — системная страница БОС. Одна страница может стоять в обоих окнах сразу.
- ПЗУ-страницы окна 1: 0 = 328 (100000) + 329 (120000) — БЕЙСИК ч. 2, 3; 1 = 327 (100000) +
  325 (120000) — БЕЙСИК ч. 1 + расширение БОС; 2 и 3 — пусто (чтение → зависание, вектор 4, как у GID).
- Старт ЦП: `0177716` читается как `0140000` → первая команда БОС. ПЗУ 324 начинается
  `MTPS #340; JMP 0140300`; таблица точек входа БОС с 0140010.

### 2.2 Регистр 0177716, запись (два регистра, разводка по биту 11)

**Бит 11 = 1 — регистр памяти** (маска GID `077433`):

| Биты | Назначение |
|---|---|
| 14–12 | код ОЗУ-страницы для окна 040000 |
| 11 | = 1 |
| 10–8 | код ОЗУ-страницы для окна 100000 |
| 4 | ПЗУ-страница 3 в окно 100000 |
| 3 | ПЗУ-страница 2 |
| 1 | ПЗУ-страница 1 |
| 0 | ПЗУ-страница 0 |

- **Код → страница: `{1, 5, 2, 3, 4, 7, 0, 6}`** (код 0 → стр. 1, код 1 → стр. 5, …, код 6 → стр. 0);
  обратно страница → код: `{6, 0, 2, 3, 4, 1, 7, 5}`.
- Несколько бит ПЗУ сразу: приоритет бит 0, затем 1, 3, 4 (GID).
- Включение питания: регистр = 0 → оба окна — страница 1, ПЗУ в окне 1 нет. БОС сам ставит
  системную раскладку; «системное» значение в GID — `054002` (стр. 7 в окно 0, ПЗУ-стр. 1 в окно 1).
- Регистр не читается (БОС хранит копии в 0114 и 0116). Документация: только словом; GID
  принимает байты, сдвигая нечётный байт в старший — делаем так же.
- Команда `RESET` на карту не влияет (внешняя защёлка, не INIT).

**Бит 11 = 0 — регистр ленты / динамика** (маска GID `010344`):

| Бит | Назначение |
|---|---|
| 12 | блокировка клавиши СТОП (1 = СТОП не работает) |
| 7 | мотор магнитофона (1 = стоп) |
| 6, 5, 2 | выход на ленту и динамик — те же три бита (маска `0144`), что на БК-0010 → уровень 0..7 |

### 2.3 Регистр 0177716, чтение

`0140000 | 0200 | бит 6 (= 0, пока удерживается клавиша) | бит 5 (вход ленты, у нас 0) |
бит 2 («была запись в 0177716», гасится чтением; ставится и по HALT/СТОП)`.

### 2.4 Регистр 0177662, запись (маска `0147400`)

| Бит | Назначение |
|---|---|
| 15 | экранный буфер: 0 = страница 5, 1 = страница 6 |
| 14 | кадровое прерывание (вектор 0100): **0 = разрешено, 1 = запрещено** (подтверждено в ПЗУ БОС `.BTIM`; emuverse/форум — наоборот, см. И20) |
| 11–8 | номер палитры 0..15 |

- Включение питания: `047400` — палитра 15, прерывание запрещено, страница 5.
- Чтение — по-прежнему регистр данных клавиатуры. На БК-0010 запись сюда не принимается
  (вектор 4) — на этом держится детект машины прошивкой СМК, поведение 0010 не менять.
- Байтовая запись — как у GID (`src &= 0377; if (addr & 1) src <<= 8`).
- `RESET` регистр не трогает.

### 2.5 Регистр 0177664

Без изменений (биты 0–7 строка, бит 9 полный/малый экран, бит 8 не реализован); на 11М
байтовая запись в старший байт игнорируется (GID `Board_11M.cpp:235-243`).

### 2.7 Тактовая частота и развёртка

- ЦП **4 000 000 Гц** (И22; 4608 кГц — ранние БК-0011). 037 остаётся на **6 МГц** от своего
  кварца, геометрия та же: 384 CLKIN × 320 строк (256 видимых + 64 гашения) = 20,48 мс = 48,83 Гц.
- ⇒ **81920 тактов/кадр, 256 тактов/строка, 1 такт ЦП = 1,5 CLKIN** (на 0010 — 61440, 192, 2).
- Таймер ВМ1 0177706/0177710/0177712 — CLC/128 = 32 мкс (измерено Багаевым), т.е. период в
  тактах тот же 128. Флаг готовности клавиатуры гаснет через 900 тактов (GID — для обеих машин).
- НГМД: слово раз в 64 мкс = **256 тактов** (сейчас `Fdd::PERIOD_TICKS = 192`).
- Реальная скорость 11М ≈ 0010 × 1,26 при частоте × 1,33 (§14.11) — ориентир для модели ожиданий.

### 2.8 Фаза кадрового прерывания по RTL 037

`va_037.v:239-241`:
```
SYNC2 = ~(VGATE & (LC[5:2] == 4'b1010) & ~(LC[0] & LC[1]));
SYNC5 =  VTSYN | (SYNC2 & ~HGATE);
PIN_nVSYNC = ~(SYNC2 ^ SYNC5);
```
В гашении LC[5:0] идёт 63 → 0 (строки кадра 256..319), SYNC2 активен при LC[5:0] ∈ {42, 41, 40}
⇒ импульс nVSYNC занимает **строки 277–279**, т.е. начинается на 21-й строке гашения, за **43
строки до строки 0** видимого поля. IRQ2 ВМ1 — по фронту; берём начало импульса (строка 277),
неопределённость ±3 строки отметить в доке. GID даёт прерывание в начале гашения (строка 256) —
на 21 строку раньше; наш эмулятор сейчас — на строке 0 (на 43 строки позже RTL).

### 2.9 Векторы и прочее

- 0100 — кадровый таймер (IRQ2), разрешается битом 14 0177662 = 0; тот же вектор у контакта B1 УП.
- 004 — СТОП / HALT / зависание; СТОП блокируется битом 12 ленточного регистра.
- 060 / 0274 — клавиатура, без изменений. 0270/0272 — прерывание параллельного порта (не эмулируем).
- БОС при старте: клавиша удержана → монитор `@`; есть контроллер НГМД → `JSR 0160000` (загрузка с
  диска, приводы 0 и 1); иначе перебор ПЗУ-блоков с первым словом `000240` сверху вниз; иначе
  монитор. Без диска и клавиш стартует БЕЙСИК («МОНИТОР БК-0011 В1.8», «БЕЙСИК БК11/10»).
  Ручная загрузка с диска из монитора: `B` / `NB`.
- EMT 36-перехват 0010 (`Board::handleEmt36`) к БОС не относится — на 11М отключить.

### 2.10 AY-3-8910 / YM2149 на порту 0177714 (GID `Board.cpp:1184-1193`, `AYSnd.cpp`)

- Запись **словом** → адрес регистра: `reg = (~word) & 0x0F`.
- Запись **байтом** → данные: `data = ~byte`; байт по нечётному адресу 0177715 даёт данные 0xFF.
- Чтение 0177714 — джойстик; AY не читается. Запись по-прежнему попадает в `portOut_`.
- Пример из форума: `MOV #100007,R0; COM R0; MOV R0,@#177714` (регистр 7), затем
  `MOV #100005,R0; COMB R0; MOVB R0,@#177714` (данные 5).
- Такт по умолчанию **1 714 286 Гц** (12 МГц / 7, «Мультизвук»); варианты 1,75 / 1,7734 / 1,5 МГц.
  Модель YM2149: 32-уровневая логарифмическая таблица громкости (`emu2149.cpp:106-116`),
  значение регистра громкости `v` → ступень `((v & 15) << 1) + 1`; формы огибающей <4 → 9, 4–7 → 15.
- Ковокс (8-битный ЦАП на младшем байте), TurboSound (0377/0376 — выбор чипа), AZБК
  (0177172–0177175) — вне объёма.

- `Vp037`: `syncToVsync()` — состояние счётчиков в начале импульса nVSYNC. Вычислить один раз
  (`syncToFrameTop()` + `tick(277 * 384)`, запомнить `pack()` в static), дальше `unpack` +
  `frameClk_ = 0`. Отсчёт `frameClk_` — от VSYNC. Аксессоры: `frameLine()` (0..319 от VSYNC),
  `visibleLine()` = `frameLine() - 43` (0..255 в поле, иначе <0 или ≥256),
  `lineWord()` = `(frameClk_ % 384) / 8` (видимые слова 0..31, гашение 32..47 — HGATE=0 в начале
  строки после синка, см. `Vp037.cpp:15-25`). Тест геометрии (`cpu_tests.cpp:358-392`) дополнить:
  43 строки гашения до поля, 21 после, `visibleLine()` пробегает ровно 0..255.
- `Board::beginFrameRaster()` (`Board.cpp:93-96`) → `vp037_.syncToVsync()`; `deliverFrameInterrupts()`
  там же — момент VSYNC становится границей кадра эмулятора для обеих машин (`runFrame`,
  `runFrameSlice`, `runUntil`, `runUntilReturn` — `Board.cpp:732, 750, 763, 773`). Для 11М взводить
  `irqFramePending_` только при `!(reg662_ & 040000)`.
- Построчная отрисовка: `renderScanlinesUpTo()` (`:99-105`) работает по `visibleLine()`
  (отрицательные → ничего); добавить `renderedWord_` и `Board::flushRaster()` — дорисовать текущую
  строку от `renderedWord_` до `lineWord()` текущими палитрой/страницей/скроллом. Вызывать из записи
  в 0177662 и 0177664. `Screen::renderLine` → `renderSpan(mem, y, scroll, fromWord, toWord)`
  (слово = 16 бит = 8 цветных точек × 2 = 16 текселей; моно — 16 точек); `renderLine` =
  `renderSpan(…, 0, 32)`. Палитра — `palette_`.
- Для 11М построчная отрисовка **включена по умолчанию** (`--no-scanline` выключает); для 0010 —
  как сейчас (ВЫКЛ, `--scanline`). Покадровый режим рисует кадр последними палитрой/страницей.
- Тест «луч к ¾ кадра дошёл до низа» (`cpu_tests.cpp:1195-1203`) пересчитать: ¾ кадра от VSYNC =
  строка кадра 240 → `visibleLine()` ≈ 197.
- Проверить ВМ1-часть: `Board::interruptTicks`/`enterInterrupt` не зависят от строки — не трогать.

### 3.6 Модель шины для 4 МГц (`Board::busStep`, `Board.cpp:300-333`, `Vm1Timing.h`)
- Сейчас единица — четверть такта (16 единиц = окно 037 = 8 CLKIN при 2 CLKIN/такт). Ввести
  единицу **U = 1/12 такта ЦП** — общий знаменатель четверти такта и полупериода CLKIN при
  1,5 CLKIN/такт. Параметры в U:

  | Величина | 0010 (3 МГц) | 11М (4 МГц) |
  |---|---|---|
  | такт ЦП | 12 | 12 |
  | полутакт (единица `Vm1Sched`) | 6 | 6 |
  | четверть такта | 3 | 3 |
  | CLKIN | 6 | 8 |
  | период решений окна 037 (8 CLKIN) | 48 | 64 |
  | задержка запроса (5 четвертей) | 15 | 15 |
  | ответ ЦП после решения (11 четвертей, округление к такту) | 33, `& ~(12-1)` → к границе такта | то же |
  | быстрая память: чтение/запись/RMW (8/10/14 четвертей) | 24/30/42 | 24/30/42 |
  | `kRomReadExtra` (4 четверти) | 12 | 12 |

  Для 0010 все величины кратны 3 → результаты тождественны текущим; **регрессионный критерий —
  существующие тесты XOP2 (обе фазы), XOP2N, RTL-программы 2000/2001, 45com-lo 45/45 проходят без
  правок эталонов.** Какие из задержек «037-сторонние» (должны масштабироваться с CLKIN) и какие
  «ВМ1-сторонние» (с тактом) — на 0010 неразличимо; на 11М это и есть предмет калибровки
  (кандидаты: задержка запроса 5 четвертей и 11 четвертей ответа).
- `phi` (фаза включения питания, `cpuPhase_`): на 11М период 64 U при такте 12 U → картина
  повторяется каждые 2 такта (НОК 64 и 12 = 192 U = 16 тактов = 3 окна… проверить: 192/64 = 3
  окна на 16 тактов) → средние по команде дробные, что и показывает таблица Manwe («дробные
  средние», `docs/slow-memory-timing.md:353`). `--cpu-phase 0|1` сохранить как две фазы; остальные
  сдвиги — позже.
- `busClass` (`Board.cpp:177-182`) для 11М: ДОЗУ = `addr < 0140000`, если в окне 1 стоит ОЗУ-страница;
  ПЗУ-страница в окне 1 и 0140000–0177577 = `BusRom`; `>= 0177600` = `BusFast`. `kRomReadExtra`
  оставить 4 четверти (GID для 11М тоже даёт ROM +4).
- `busFrac_`/`busSkew_` в снимке — в единицах U (формат снимка 11М новый, 0010 — пересчитать ×3
  при чтении старого).
- Калибровка: `45com-lo.bin` на 11М (загрузки `.BIN` нет → собрать дисковый образ с автозапуском
  или положить код в ОЗУ стр. 0 через MCP `bk_write_mem` и `bk_set_reg PC`), сверить с PNG Manwe.
  Результат и расхождения — в `docs/bk0011m.md`.
- Фоллбэк `--no-arb037` → `timingFast` + штраф ПЗУ, как сейчас.

### 3.7 AY-3-8910 / YM2149 (`src/core/Ay8910.h/.cpp` — новое, без Qt)
- Своя компактная реализация по семантике emu2149 (ссылки на `emu2149.cpp` в комментариях):
  16 регистров; 3 тональных генератора (период × 16 CLK, счётчик каждые 8 CLK); шум (LFSR 17 бит,
  период × 16 CLK); огибающая (16 ступеней на 32-уровневой шкале, период × 256 CLK, формы 0–15 с
  приведением <4 → 9, 4–7 → 15); таблица громкости YM2149 на 32 уровня; громкость `((v&15)<<1)+1`,
  бит 4 регистра громкости — режим огибающей; регистр 7 — маски тон/шум; регистры 14/15 (порты
  В-В) — хранить, не использовать.
- API: `setClock(int hz)` (по умолчанию 1 714 286), `reset()`, `writeAddress(uint8_t)`,
  `writeData(uint8_t)`, `int sample(double dtSec)` — продвинуть на `dt` и вернуть моно-смесь
  A+B+C (внутренний дробный шаг, как `PSG_calc`), `const uint8_t* regs()`, `uint8_t address()`,
  `pack/unpack` для снимка.
- Подключение в `Board::ioWrite(REG_PORT)` (`:1173-1178`): при `ayOn_` — слово → `writeAddress(~lo)`,
  байт → `writeData(~lo)` (нечётный адрес → 0xFF); `portOut_` пишется как и раньше.
  `setAy(bool)`, `ay()`; по умолчанию **ВКЛ на 11М, ВЫКЛ на 0010** (на 0010 ковокс/принтер в тот же
  порт дали бы шум; переключатель общий для обеих машин).
- Микс: `Speaker::setAy(Ay8910*)`; в цикле `feed()` (`Speaker.cpp:17-57`) на каждый выходной
  отсчёт `v += ay->sample(take)` после DC-блокера динамика, до клампа ±32767; амплитуда AY на
  полной громкости ~±10000 (динамик качается ±18000). `Speaker::clear()` AY не трогает.
- MCP `bk_io_state`: строка AY (адрес, 16 регистров восьмерично, расшифровка периодов/громкостей);
  `bk_audio` — без изменений (моно 44100).
