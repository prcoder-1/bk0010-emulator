# Магнитофон: кассеты .WAV

Кассета — звуковой файл `.wav`: запись с настоящей ленты или результат конвертера
`.BIN → .WAV` (bk-wav/bkbin2wav.c, raydac/bkbin2wav, веб-конвертер
thesands.ru/bk0010/wav-converter и его CLI-версия bin2wav). С кассетой работают двумя
путями:

* **Мгновенно, как с .BIN.** Декодер разбирает сигнал так, как это делает драйвер ПЗУ, и
  программа с кассеты грузится сразу: позиционный аргумент `игра.wav`, «Файл → Загрузить
  программу», MCP `bk_load`. `игра.wav#N` — N-й файл ленты. Кассета остаётся в
  магнитофоне за этим файлом: следующие файлы программа читает с неё сама.
* **Магнитофон.** Сигнал подаётся в разряд 5 регистра `0177716` по эмулируемому времени.
  Читает его сам драйвер ПЗУ (EMT 36 монитора БК-0010, `.BMB10` БОС БК-0011М) или любой
  свой загрузчик программы, например турбо-загрузчик Maxim. Так грузится всё, что
  грузится на живой машине, с теми же сбоями.

Код: `src/core/Tape.{h,cpp}` (WAV, компаратор, декодер, магнитофон), `Board`
(разряд 5 и двигатель в `0177716`, EMT 36, снимок), `src/ui/TapeDialog`, меню
«Магнитофон», MCP `bk_tape`.

## Формат записи

Драйвер ПЗУ (монитор 116640–117460, разобран в БК-docs §11) и все конвертеры пишут
один формат. Элемент — период из двух полупериодов разной полярности; L — период
пилот-тона:

| Элемент | Период |
| --- | --- |
| синхроимпульс, «0» | L |
| «1» | 2L |
| маркер | ≈4L (полупериод 2L) |

Файл: длинный пилот-тон → маркер → «1» → короткий пилот-тон → маркер → «1» → заглавие
(адрес, длина, 16 байт имени) → короткий пилот-тон → маркер → «1» → массив и КС
(слово, сумма байтов с переносом). Каждый бит — синхропериод и информационный период.

Как читает драйвер (так же устроен декодер `tapeDecode`):

* пилот-тон: 04000 стабильных периодов, затем среднее по 0200 → порог 1,5L (ячейка 314);
* маркер — полупериод длиннее порога; его уровень задаёт фазу (ячейка 300: 377 —
  сигнал инверсный), полупериод длиннее 3L — сбой, поиск с начала;
* бит: дождаться конца текущего периода (это и есть синхроимпульс), измерить следующий;
  длиннее порога — «1». Длительность синхроимпульса не проверяется, поэтому «ускорение
  на 11%» веб-конвертера (синхроимпульс в 3 сэмпла вместо 4) читается.

Конвертеры различаются только длительностями и тем, с какого уровня начинается период.
bkbin2wav.c начинает с низкого, его записи драйвер читает в инверсной фазе.
Длительность синхроимпульса у них тоже своя: L, 2 из 3 или 3 из 4 сэмплов.

## Турбо-формат Maxim

Веб-конвертер в режиме «БК0010 3 МГц — загрузка в 8 раз» пишет две записи подряд,
40000 Гц:

1. Загрузчик `maxim-loader` (Manwe/SandS 2019) штатным форматом: адрес 0760, длина 0302.
   Первые 8 слов — `001000`. Они затирают стек драйвера, и возврат из EMT 36 уходит
   прямо в 01000.
2. Турбо-поток: пилот 1024 × (3 сэмпла высокий + 3 низкий), маркер 12 + 12, биты по
   **длительности высокого уровня**: 1 сэмпл — «0», 3 — «1». Затем тело, дополненное до
   чётной длины, и КС.

Загрузчик ставит адрес и длину в своём коде (слова 9 и 11 тела), адрес пуска — в
`JMP @#…` после проверки КС. Декодер узнаёт загрузчик по этим командам и читает
турбо-поток следом. Загрузчик меряет только высокий уровень, так что полярность ему
важна: высокий уровень WAV даёт 1 в разряде 5, как у GID. BKBTL инвертирует, и
Maxim у него не грузится.

## Компаратор входа

`tapeBinarize` моделирует разделительный конденсатор и компаратор на входе БК: порог
посередине между огибающими максимума и минимума (постоянная 10 мс), гистерезис 10%
размаха, в тишине уровень не меняется. Постоянная составляющая и медленный дрейф
записи с ленты не мешают. Чтение WAV: PCM 8/16/24/32, float 32/64, EXTENSIBLE,
каналы смешиваются.

## Магнитофон (`bk::Tape`)

* Позиция — в сэмплах, время — такты ЦП платы. Сэмпл = такт × частота WAV / частота ЦП:
  точно для 3 и 4 МГц, без привязки к кадрам и звуковой карте.
* Кнопки: «Воспроизведение», «Стоп», перемотка, позиция в начало файла.
* **Автопуск** (по умолчанию вкл): лента трогается сама, когда драйвер ПЗУ начинает её
  читать. Признак — команда по адресу из диапазона чтения ленты в ПЗУ: монитор
  116640–117460, БОС 155662–156502. Так ведёт себя пользователь, который нажимает
  «Воспроизведение», когда БК ждёт ленту. Двигатель (разряд 7) для этого не годится:
  его переключает и звук игр.
* Лента, тронувшаяся по автопуску, встаёт, когда драйвер выключает двигатель (`MOV
  #220,(R3)`), как магнитофон с ДУ. Иначе многофайловая кассета ушла бы вперёд, пока
  программа работает. Исключение — загрузчик Maxim и его турбо-поток: загрузчик
  читает его сразу, двигатель не трогая.
* **ДУ** (по умолчанию выкл): лента идёт только при включённом двигателе (разряд 7 = 0).
  Так работала «Электроника 302» с кабелем ДУ.
* Пока кассета вставлена, **EMT 36 не перехватывается**: файлы читает и пишет драйвер ПЗУ
  с ленты. Чтобы снова грузить файлы хоста, кассету надо извлечь.
* Снимок (`BKX1`) хранит позицию ленты, кнопки, двигатель и ДУ, но не саму кассету.
* GUI с «Ускорять эмуляцию, пока идёт лента» (по умолчанию вкл) гонит эмуляцию без
  привязки к реальному времени, пока лента движется. 46-секундная кассета проходит
  примерно за 4 секунды.

## Как пользоваться

GUI, меню «Магнитофон»: «Вставить кассету», «Оглавление кассеты» (файлы, адреса, КС,
время; загрузить программой, поставить ленту на файл, сохранить .BIN), «Воспроизведение»,
«Перемотать», «Извлечь» и настройки (автопуск, ДУ, инверсия, ускорение). Состояние ленты
показано справа в строке состояния. «Файл → Загрузить программу» принимает и .wav; при
нескольких программах на кассете спрашивает, какую грузить.

Загрузка командой БК:

* БК-0010-01 без СМК: Бейсик → `MON` → `М` (кириллица) → имя → загрузка → `С` (пуск).
  Имя набирается точно как на ленте; строчные русские буквы с клавиатуры БК так просто
  не набрать.
* БК-0011М: монитор БОС → `L` → ВВОД (пустое имя — первый файл) → `G`. `BLOAD` Бейсика
  11М ищет имя 6.3 («Desant.BIN»), длинное имя с ленты он пропускает.

Командная строка:

```sh
bk0010-emulator ARKANOID.wav                 # программа с кассеты сразу
bk0010-emulator "КАССЕТА.wav#3"              # третий файл кассеты
bk0010-emulator --bk10 --no-smk --tape LRUNNER.wav   # кассета в магнитофоне
bk0010-emulator --wav2bin КАССЕТА.wav        # оглавление и файлы в .BIN
```

`--tape-play` сразу нажимает «Воспроизведение» (для своих загрузчиков без ПЗУ),
`--tape-remote` включает ДУ.

MCP: `bk_load {"path": "x.wav"}`, `bk_tape {"action": "insert"|"list"|"play"|"stop"|
"rewind"|"seek"|"run"|"save"|"eject"}`. `run` гонит кадры, пока лента грузится: от
пуска до остановки. Рецепт — [`mcp-debugging.md`](mcp-debugging.md).

## Проверка

* `cpu_tests` («Магнитофон»): записи всех трёх конвертеров, с шумом, дрейфом и
  инверсией, две записи подряд, неверная КС, турбо Maxim, WAV 16 бит стерео и 8 бит.
  Сквозные тесты: драйвер ПЗУ (EMT 36) читает файл с сигнала, загрузчик Maxim
  принимает турбо-поток и запускает программу, .wav грузится как .BIN, снимок.
* Корпус `~/emulators/БК-0010-01/wav` (55 кассет: 47 турбо Maxim, 8 стандартных):
  декодер читает все, КС верна; тела совпадают с исходными .BIN. Отличия есть: турбо
  дописывает байт к нечётной длине, в DIDAY.wav другая версия игры. Через сигнал
  (`М` + имя в мониторе) грузятся 54 кассеты. Не грузится «Диверсант»: его имя строчными
  буквами не набирается. Записи raydac/bkbin2wav.py (11025 и 22050 Гц) драйвер тоже
  читает. Вывод bk-wav/bkbin2wav.c, собранного под 64 бита, — не WAV: wavlib пишет
  поля размеров 8-байтными `long`.

Не сделано: запись на ленту в WAV (EMT 36 «запись» при вставленной кассете уходит в
сигнал выхода, которого никто не пишет).
