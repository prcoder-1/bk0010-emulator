# Винчестер (НЖМД): контроллеры СМК-512 и «Самара», образы HDI

Эмулируются два контроллера винчестера IDE, у обоих по два накопителя ATA (master и
slave) и образы в формате **HDI** эмулятора GID:

| | СМК-512 («АльтПро») | «Самара» (КЖД Лугова) |
| --- | --- | --- |
| Регистры | `0177740–0177757`, CS1 — нечётные `0177741/0177743` | `0177640–0177656`, CS1 — `0177620/0177622` |
| Драйвер и загрузка | прошивка платы `roms/smk512.rom` (v2.05), перехват адреса пуска | прошивка КНГМД `roms/samara.rom`, автозагрузчик `0160000` сначала пробует винчестер |
| Нужна плата СМК-512 | да — канал IDE её узел | нет (на БК-0010 её ОЗУ нужно загрузчику, как и дискете) |
| Разметка диска | таблица в блоке 7 | таблица в блоке 1 |
| Машины | БК-0010-01, БК-0011М | БК-0011М (для неё сделан), БК-0010-01 |

```sh
./build/bk0010-emulator --machine bk11m maxvel.hdi    # позиционный .hdi = --hdd
./build/bk0010-emulator --hdd c.hdi --hdd-b d.hdi --hdd-rw
./build/bk0010-emulator --hdd-ctl samara disk.hdi     # контроллер явно
```

**Какой контроллер.** По умолчанию (`--hdd-ctl auto`) — по разметке образа
первого подключённого винчестера (`bk::hdiLayout`, `Board::resolveHddController`):
таблица дисков «Самары» в блоке 1 — её контроллер, иначе СМК. `--hdd-ctl smk|samara`,
MCP `bk_reset {"hdd_ctl": …}`, меню «Файл» → «Контроллер винчестера» задают его явно
(действует со следующего подключения образа).

GUI: «Файл» → «Подключить винчестер (HDI)…» (с включением питания), «…второй
винчестер (slave)…» (на ходу), «Отключить винчестеры». MCP: `bk_reset {"hdd": "…"}`
(`""` — отключить, `hdd_rw` — писать в файл, `hdd_ctl`), `bk_io_state` показывает
контроллер, регистры, геометрию и **логические диски** по разметке, `bk_machine` —
подключённые образы; сервер понимает и `--hdd`, `--hdd-ctl`. В панели Soft-ICE
«СИСТ. РЕГИСТРЫ» — строка `НЖМД Сам|СМК к<команда> LBA <n> ст<статус>`.

**СМК.** Винчестер — узел самой платы, поэтому образ включает СМК-512 (на этот
запуск, настройку не меняет; с `--no-smk` вместе не запускается). Без явного
`--disk-rom` контроллер с винчестером получает прошивку СМК вместо драйвера 326;
отключение последнего винчестера возвращает 326. Регистры НЖМД стоят на шине, только
пока плата установлена **и** подключён хотя бы один образ.

**«Самара».** Контроллер разработки А. Ю. Лугова для БК-0011М — предшественник
винчестерной части СМК (БК-docs §13.12). Ставился внутрь машины, а к его краевому
разъёму припаивался обычный КНГМД с изменённой прошивкой, где драйвер винчестера
стоит рядом с драйвером дисковода. Поэтому у эмулятора это КНГМД (`Kngmd`) с ПЗУ
`roms/samara.rom` плюс канал IDE на регистрах «Самары»; плата СМК-512 не нужна и не
мешает. Регистры на шине, пока подключён образ. Загрузка: на БК-0011М БОС сама
находит контроллер и зовёт `0160000`, на БК-0010 — как с дискетой, из поднятого
монитора (`Board::bootFromHdd`). Автозагрузчик четыре раза ждёт готовности
винчестера, читает блок 1, заголовок диска автозагрузки и его первый блок в
`01000`, проверяет `NOP` в начале и передаёт управление с номером диска в R0; если
не вышло — A: и B:.

`roms/samara.rom` — прошивка `HDD+FIS.ROM` из архива контроллера (файл `.BIN`:
адрес 0160000, длина 007764) без заголовка, дополненная нулями до 4 Кбайт; побайтово
совпадает с `DISK_SAMARA_HDD+FIS.rom` из GID. Вариант `HDDS_M+FIS` (master/slave)
длиннее окна ПЗУ на 28 байт и не используется.

На БК-0010-01 загрузчику нужна память на месте Бейсика: блок читается в
`01000–01777`, а Бейсик держит стек в `01762`. У КНГМД БК-0010-01 там было своё ОЗУ
16 Кбайт; у нас его даёт СМК-512, поэтому с «Самарой» на БК-0010 плата включается
так же, как для дискеты (если её не сняли ключом).

## Формат HDI

Источник — исходники GID (`shared/HDIStuff.cpp`, `devemu/HDD.cpp`); утилиты
HDDImgMaker и BKHDDTool из комплекта его эмулятора делают такие образы из дампов
реальных дисков АльтПро и «Самары» и обратно ([описание HDDImgMaker][hddim],
[BKHDDTool][hddtool], [форум zx-pk.ru][zxpk]).

| Смещение | Содержимое |
| --- | --- |
| `0–511` | паспорт накопителя — ровно то, что он отдаёт по IDENTIFY DEVICE: слово 1 — цилиндры, 3 — головки, 6 — секторы на дорожке, строки модели/серийного номера с переставленными байтами (как в ATA); байт 510 = `0xA5`, байт 511 — дополнение суммы байтов 0..510 до нуля |
| `512 + n·512` | сектор LBA `n` = `(c·H + h)·S + s − 1` |

Размер файла — `512 + C·H·S·512`. Паспорт лежит **в прямом коде**, а секторы — в
том виде, в каком их хранит сам накопитель, то есть **в инверсном коде** относительно
процессора: шины БК и IDE разводят инвертирующие буферы платы (БК-docs §15.12, «все
данные представлены в инверсном коде»). Поэтому `.img` (сырой дамп CF/HDD) → `.hdi` —
это просто приписать паспорт, данные не меняются; HDDImgMaker при опознании разбивки
АльтПро так и читает геометрию: блок 7 после инверсии, слова 253–255.

Не путать с форматом утилиты `bkhdutil` ядра MiSTer: там первый блок — таблица
логических дисков с подписью `BKHD` ([MiSTer forum][mister]).

## Шина СМК

| Адрес | Чтение | Запись |
| :-: | --- | --- |
| `0177740` | статус | команда |
| `0177742` | головка, накопитель, LBA | то же |
| `0177744` / `0177746` | цилиндр, ст. / мл. байт | то же |
| `0177750` | сектор | то же |
| `0177752` | счётчик секторов | то же |
| `0177754` | ошибка | features |
| `0177756` | данные (слово) | данные |
| `0177741` | адрес накопителя (3F7) | — |
| `0177743` | второй статус (3F6) | управление: разряд 2 — SRST |

* **Инверсия в обе стороны** — в `Board::MpiMux` (`hddBus`), модель накопителя
  (`src/core/Hdd.{h,cpp}`) работает в обычной логике ATA. Восьмиразрядные регистры
  читаются со старшим байтом `0` (у GID так же).
* **Нечётные адреса — отдельные регистры, и A0 различается даже при словном
  обращении.** ПЛИС выбирает CS1 по `A0` (`smk64.vhd`: `rt5_address` включает
  `a(0)`), а драйвер в ПЗУ платы делает программный сброс словом:
  `CLR @#177743` / `MOV #6,@#177743`. Поэтому `Memory` передаёт устройству МПИ адрес
  **с A0** и при словных обращениях (ВМ1 его не обнуляет), а выравнивает уже
  `MpiMux` — для СМК и дисковода договор прежний. Чтение `0177741`/`0177743` отдаётся
  в обе половины слова: `MOVB` берёт старшую, `MOV` — младшую (как ведут себя
  неподключённые линии старшего байта на живой плате, неизвестно).
* Два накопителя на одних проводах: запись видят оба, отвечает выбранный разрядом
  DEV (`0177742`, разряд 4), невыбранный отдаёт единицы — для БК нули.

## Шина «Самары»

| Адрес | Чтение | Запись |
| :-: | --- | --- |
| `0177640` | статус | команда |
| `0177642` | головка, накопитель (SDH) | то же |
| `0177644` / `0177646` | цилиндр, ст. / мл. байт | то же |
| `0177650` | сектор | то же |
| `0177652` | счётчик секторов | то же |
| `0177654` | ошибка | предкомпенсация (features) |
| `0177656` | данные (слово) | данные |
| `0177620` | адрес накопителя (3F7) | — |
| `0177622` | второй статус (3F6) | управление (SRST) |

Тот же блок, что у СМК, сдвинутый на `0100`; регистры CS1 стоят по чётным адресам,
поэтому хитрость с A0 не нужна (`Ide::decodeSamara`). Данные так же инверсные: прошивка
пишет `COM` от номеров цилиндра и сектора, команды 337/317 — это ~040 (чтение) и
~060 (запись), сброс — запись 0, затем 377 в `0177622`. Регистры — те же, что
декодирует GID (`FDDController.cpp`, `BK_DEV_MPI::SAMARA`).

## Разметка: логические диски

`bk::readHddMap` разбирает обе разметки (по данным после инверсии), их показывает
`bk_io_state`:

* **«АльтПро» / СМК** — блок 7, с конца: слова 255/254/253 — цилиндры, головки,
  секторы; 252 — число дисков и (старший байт) диск автозагрузки; дальше пары
  «`(цилиндр << 4) | головка` начала, длина» и контрольная сумма от `012701`
  (так её читают HDDImgMaker и `bkhdd`);
* **«Самара»** — блок 1: номер диска автозагрузки, H·S, `S | (H−1) << 8`, с третьего
  слова — номера первых блоков дисков двойными словами до нуля. Первый блок диска —
  заголовок: номер диска (2 = C:), ёмкость, флаги (010 — защита от записи, 020 — от
  чтения), адреса блока параметров (2000) и загрузчика (1000), значение `0177716`
  (014400); данные — со следующего блока. Блок 2 — таблица плохих блоков (не
  используется). Формат — по `samara.txt` и исходнику прошивки (`UNI++.MAC`) из архива
  контроллера, проверен на `test_samara.hdi` из GID. ⚠ Утилита `bkhdd` (Terra, 2016)
  пишет заголовок без слова флагов, сдвигая адреса на слово.

## Модель накопителя

Порт `CHDD` из GID, но команды исполняются сразу, без потока: `BSY` процессору не
виден. Команды: чтение (`20/21`), запись (`30/31/3C`), верификация (`40/41`),
позиционирование (`7x`), рекалибровка (`1x`), IDENTIFY (`EC`), диагностика (`90`),
инициализация параметров (`91`, игнорируется — геометрия своя), чтение/запись буфера
(`E4/E8`), формат дорожки (`50`, таблица чередования принимается и выбрасывается),
энергосбережение (`E0–E3, E6`). Адресация CHS и LBA. Неизвестная команда, как у GID,
считается выполненной.

Отличие от GID: после программного сброса накопитель снова работает, даже если
прошлая команда кончилась ошибкой (у GID такой накопитель оставался «мёртвым» до
выключения питания).

**Запись.** По умолчанию образ открывается только на чтение, как и дискета: сектора,
записанные БК, живут в памяти поверх файла (`bk_io_state` показывает, сколько их) и
пропадают при отключении. `--hdd-rw` (MCP `hdd_rw`) пишет прямо в файл.

## Проверено

* `maxvel.hdi` (1 Гбайт, C/H/S 1985/16/63, 27 логических дисков; из архива
  `maxvel_hdd_bk.rar`) — на обеих машинах MBR загружает **MKDOS**, видны каталоги диска
  `C:`, переход на логический диск `J:` читает его каталог.
* `test.hdi` из комплекта GID (20 Мбайт, 40/16/63) — на обеих машинах грузится
  **ANDOS 3.30**.
* `test_samara.hdi` из комплекта GID (28 Мбайт, 600/4/24, разметка «Самары», 4 диска
  по 2559 блоков) — на БК-0011М с винчестера грузится **CSIDOS 3.38** («Samara-city»),
  на диске C: видны логические диски и программы обслуживания `srv213`, `srvbk1/2`;
  SRV (Лугов) показывает «винт 28 Мб, 4 гол., 30 сект. на дорожку, 1130 цил-ра» (числа
  восьмеричные) и автостарт с C:. CSIDOS — система для 11М, на БК-0010 её загрузчик
  возвращается в монитор.
* `cpu_tests`, «Самара»: дешифратор регистров, опознание разметки, таблица дисков,
  загрузка синтетического диска C: через `0160000` на БК-0010 и через БОС на 11М
  (R0 = 2), `--hdd-ctl smk` перекрывает разметку.
* `cpu_tests`: синтетический образ — паспорт, сброс словом в `0177743`, IDENTIFY через
  инвертирующую шину, двухсекторное чтение по CHS, запись поверх файла (файл не
  меняется), выход за геометрию (`ERR`, `IDNF|ABRT`), отсутствие регистров без платы.

## Чего нет

* Сырых дампов (`.img` без паспорта): геометрию можно было бы взять из блока 7
  АльтПро, как это делает HDDImgMaker, но `.img` уже занято образами дискет.
* Состояния винчестера в снимках (`Ctrl+S`, `bk_state_save`) — как и у дискет; образ
  остаётся подключённым.
* Тайминга: обмен мгновенный.
