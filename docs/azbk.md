# Контроллер AZБК

AZБК (MAXIOL) — плата в разъёме МПИ, которая забирает себе почти всю «обвязку» БК:
маппер на 32 Мбайт, свой VGA 1024×768 со слоями и палитрой на 32768 цветов, блиттер,
два AY, Covox, DMA-звук, контроллер дисков с карты SD, EEPROM, часы, ГПСЧ, сетевую карту.
Эмулируется всё, что видит программа, — на БК-0011М и на БК-0010-01; сеть — со стеком
TCP/IP самой прошивки и выходом в сеть хоста (раздел «Сеть»). Код — `src/core/Az*.{h,cpp}`,
тесты — разделы «AZБК» в `cpu_tests`.

## Включение

| Где | Как |
| --- | --- |
| Командная строка | `--az` / `--no-az`; `--az-sd <каталог>` — карта SD; `--az-unit N=<образ>` — диск AZn поверх AZ.INI (включает `--az`); `--az-rw` — писать в образы и на карту; `--disk-rw` — только в образы из командной строки; `--az-037` — доработка 037 (БК-0010); `--az-net <кабель>` — сеть (`tap:ИМЯ`, `macvtap:ИМЯ`, `/dev/tapN`). Образ дискеты позиционным аргументом при `--az` становится AZ0 |
| GUI | «Машина» → «Контроллер AZБК»: «Установлен» (своя настройка у каждой машины, переключение перезапускает машину), «Каталог карты SD…», «Диск AZ0…», «Диск AZ0 на запись», «Сеть (кабель сетевой карты)…» (на ходу), «Доработка 037». «Эмуляция» → «Экран VGA платы AZБК» (`Ctrl+E`): VGA платы или экран самой БК. «Отладка» → «Память AZБК по страницам…» (`Ctrl+J`) |
| MCP | `bk_reset {az, az_sd, az_unit0, az_rw, az_037, az_vga, az_net, disk_rw}`; `bk_io_state` — раздел AZ (с сетью); `bk_read_mem` / `bk_write_mem {az_addr}` — физическая память платы; `bk_screenshot` — кадр VGA (`tv: true` — экран БК) |

С платой СМК-512, КНГМД и винчестеры с шины сняты: СМК эмулирует сам AZ, диски — его.
Включение СМК при стоящем AZ только запоминается; снятие AZ возвращает СМК и контроллер
НГМД (если в приводах есть дискеты). Карта SD без AZ.INI — отказ до любых изменений:
машина остаётся, какой была (GUI не сохраняет такую настройку, `bk_reset` — тоже).
Программы `.BIN` с AZ при пуске не загружаются (AZ грузится со своих дисков): ключ `--az`
отвечает ошибкой. `bk_load` при стоящей плате кладёт файл в уже работающую систему — как
ДОС с диска AZ (сначала загрузите её): без сброса и смены машины, через окна маппера,
SP=01000; плата, включённая только сохранённой настройкой GUI, на запуск `.BIN`,
винчестера или `--smk` снимается (и при открытии `.BIN` из меню). Смена образа AZ0/AZ1
(«Диск AZ0…», дискета из меню, `bk_reset {az_unit0}`) — на ходу, без переустановки платы:
её память цела, AZ0 — с перезапуском машины, AZ1 — без.

Снимок состояния: плата — отдельный хвост «AZB1» за BKX1 (экран, отложенные запросы,
СМК до платы, регистры, ОЗУ ненулевыми страницами, открытые образы, наложения записи,
каталог и открытый файл карты с позицией). Нет хвоста — платы в снимке нет.

На БК-0010 с эмуляцией 11М (разряды BK11EMU и BRDTYPE 0177346) собственного кадрового
прерывания БК нет: его даёт плата (таймер 48 Гц или IRQ 60 Гц VGA).

```sh
bk0010-emulator --az --az-unit 0=ANDOS330.IMG          # БК-0011М: AZBOOT -> BIOS -> ANDOS
bk0010-emulator --bk10 --az --az-unit 0=ANDOS330.IMG   # то же на БК-0010-01
QT_QPA_PLATFORM=offscreen bk0010-emulator --az --frames 350 --shot bios.png   # экран BIOS
```

## Карта SD

Каталог с `AZ.INI` (как корень карты: `0:/` — это он, регистр букв в путях не важен).
По умолчанию — `roms/azbk/`: прошивка **00019** (`AZBOOT`, `AZLIB00–03`, `SETUP` из
`~/БК0010/AZ БК/Прошивки/00019`), загрузчик дисков `AZ337`, заставка, ПЗУ БК-0010 и
БК-0011М, `eeprom.dat` (тот же, что у GID и retro-tang-bk: BIOS берёт из него порядок
загрузочных дисков) и пустой `DISKS/`. Свою карту (например, распакованный
`MicroSD_image_…`) задают `--az-sd` или из меню.

Разбор `AZ.INI` — как у прошивки: `[ROM] Rnn=` — слот ПЗУ (байт `0x40000 + nn·4 Кбайт`,
страница `0100 + nn`), `[LOGO] L=` — заставка в страницу 040, `[DISKS] Dnn=` — образ
AZn, `[ALTBOOT] B4/B6=` — своя программа потоков загрузки. `[BOOT]` сборкой 19 не
читается: загрузочный диск выбирает AZBOOT по EEPROM.

Образы открываются **только на чтение**: записанное БК лежит в памяти поверх файла
(переживает сброс и команду 037, входит в снимок) и пропадает при выходе из эмулятора.
Чтобы записи БК (например, сохранения игр) оставались в образе, отдельный диск открывают
на запись: `--disk-rw` — для образов из командной строки (позиционный образ и
`--az-unit`), в GUI — «Диск AZ0 на запись», в MCP — `bk_reset {disk_rw}`; включение на
ходу сразу сбрасывает в файл то, что уже записано в памяти. То, что БК пишет на карту (EEPROM —
`EEPROM.DAT`, `AZ.INI` из Setup, файлы командами 053–055, снимки экрана 044), идёт в
свой каталог данных для каждой карты (`QStandardPaths::AppDataLocation`, на Linux
`~/.local/share/bk0010-emulator/bk0010-emulator/azbk/<имя карты>-<хеш пути>/`). При
чтении `AZ.INI`, EEPROM, образов и файлов он смотрится раньше карты (оглавление
команды 003 — только сама карта). Так `roms/azbk` в репозитории не меняется, а
настройки Setup сохраняются между запусками. `--az-rw` пишет всё прямо на карту.

## Шина

Плата стоит на всей шине (`MpiDevice::fullBus`), а не только при A15 = 1, как СМК:

- **активное окно** (разряд в 0177340) отвечает вместо БК — память и ПЗУ БК в нём не
  видны; запись в окно «только чтение» (0177342 или страница слота ПЗУ 0100–0177) —
  зависание;
- **теневое окно** (0177344, не активное): запись идёт в БК и копируется в плату — из
  копии VGA рисует старые видеорежимы;
- окно, которое плата не подключила, — **сама БК**: её ОЗУ и её ПЗУ. На БК-0011М это
  значит, что БОС в 0140000 и ПЗУ Бейсика остаются (их подменяет только «BK11 ROM
  emulation» платы); на БК-0010-01 ПЗУ Бейсика с 0120000 заблокировано (плата управляет
  памятью с 0120000), монитор — на месте. GID снимает ПЗУ БК целиком; с ним БОС уходил
  в пустое окно 1 и машина падала после BIOS;
- регистры платы — 0177000–0177577; 0177716 на чтение она складывает с ответом БК;
  0177662, 0177664, 0177716, 0177714 на запись видит вместе с БК;
- обмен, который обслужила плата, в модели шины — быстрый (`BusFast`), как ОЗУ СМК.

Пуск — всегда с 0170000 (стартовое ПЗУ в окне 15): каждый сброс БК — это `ResetCold`
платы (окна сняты, слот 0 в окне 15, разряды частоты 8:6 регистра 0177346 живут) и
перезапуск её микроконтроллера (AZ.INI заново). Первый проход AZBOOT пишет 0700 в
0177346 и подаёт команду 037 — плата перезапускает машину на ближайшей границе кадра;
второй проход измеряет частоту, рисует BIOS и грузится.

## Маппер (0177300–0177352)

16 окон по 4 Кбайт: страница — 0177300 + 2n, маски — 0177340 (подключено), 0177342
(только чтение), 0177344 (тень), управление — 0177346 (раскладка GID и БК-docs §17.4:
2 — 50 Гц, 3 — V100, 5 — ПЗУ 11М, 8:6 — частота, 9 — 037_OFF, 10 — 014_OFF, 11 —
BK11EMU, 12 — BRDTYPE, 14 — REVTYPE (только чтение), 15 — SMK_WND1), копии — 0177350
(слово режима СМК) и 0177352 (карта 0177716).

Запись в **0177716 с разрядом 11** (на БК-0011М или на БК-0010 с доработкой 037 и
отключённой 037-й) переводится в окна 0–11 (`AZ_716_In` GID): окна 0–3 — страницы
030–033, окна 4–7 — страницы кода окна 0 (код c — страницы 4c…4c+3: тень идёт по
кодам 0177716, а не по номерам страниц), окна 8–11 — код окна 1 или ПЗУ-страницы
0124/0125/0122/0123 и 0126…0131. Запись в **0177130** — строб (разряды 1, 2), затем
слово режима СМК (разряды 6:4, страница — разряды 10, 3, 2, 0) — окна 12–15 (и 8–11,
если режим отключает окно 1) по таблице GID с одной поправкой: в режимах Std10 и
Std11 в окне 0160000 — слот 8 (AZ337), как в SYS. У GID там «страница 0», и программа,
оставившая Std11 (демо leCSIcon проверяет СМК и уходит в него), звала по 0160004 тень
ОЗУ вместо драйвера диска.

## Видео

Растр VGA — 806 строк, 60 Гц, строка считается в тактах ЦП точной дробью;
отрисовка построчная (`MakeScreenLine` GID) в буфер 1024×768, готовый кадр — на
строке 769. Построчно кадр рисуется, только когда его смотрят (`Board::setAzLive`: окно
GUI с экраном VGA, запись видео) — это около трети времени эмуляции; иначе
`displayFrame()` рисует его целиком по запросу текущими значениями регистров (MCP,
`--shot`), без эффектов посреди кадра. Там же кадровое прерывание 60 Гц (V100 без 50HZ) и автоматический пуск
блиттера. Кадровый таймер «48 Гц» (V100 и 50HZ) идёт по кадру самой БК, как у GID, —
и при выключенном таймере 11М.

0177230: разряды 2:0 — режим (1, 2, 4, 8 бит на точку; 4–7 — три слоя, нуль
прозрачен), 4:3 — строка 32…256 слов, 7:6 — ×1…×8 по X, 10:9 — ×1…×4 по Y, 11 —
страницы слоёв фиксируются на кадр (без него перелистывание видно сразу), 15:12 —
рулон. Режим, строка, растяжения и скроллы фиксируются в начале кадра. Страницы
слоёв — 0177232/0177240/0177242, скроллы — 0177244…0177256 (вертикальные в обратном
порядке слоёв), палитра — 0177234 (ячейка) и 0177236 (R5G5B5; 0–255 — 256 цветов,
256–319 — 16 палитр БК-0011М, 320–335 — 16 цветов, 336–337 — монохром; стартовая
таблица — GID).

Старые режимы БК: 012100 (512 точек монохромом) и 012201 (256 цветом), страница 4 или
034 по разряду 15 0177662, палитра — разряды 11:8 0177662, скролл — 0177664. Малый
экран (0177664, разряд 9 = 0) гасит строки изображения за 192-й (у GID — строки VGA
за 192-й, это ошибка). АР2+ЛАТ переключает 012100 ↔ 012201.

## Блиттер (0177270/0177272)

По retro-tang-bk `azblit.v` (он сверен с GID и проверен на плате): пачка до 511
команд по 8 слов читается целиком; операции 000 заполнение, 010 копия, 020 наложение
(байт SRC = константе прозрачен), 030 наложение под фон, 040 сохранение фона (DST →
SRC), 050 заливка по контуру; разряд 2 — NOP, 6 — перестановка байтов, 9/10 — зеркало.
0 строк — ничего. Ручной пуск — разряд 12 при уже установленном разряде 14. За строку
VGA — 100 слов (как у GID).

## Звук

- AY1/AY2 на 0177172–0177175 (байт по чётному адресу — номер регистра, по нечётному —
  данные, слово — оба) — те же два чипа, что на порту 0177714 (у GID тоже); второй
  подмешивается с первого обращения к нему. Модель обоих задаёт 0177212, разряд 3
  (Setup, «AY Emulation»): 0 — YM2149 (32 ступени громкости), 1 — AY-3-8910 (16
  ступеней, огибающая тоже 16); BIOS пишет его по EEPROM при каждом пуске (011 для
  AY-3-8910, 01 для YM2149 при стерео Covox). Без платы чипы — YM2149.
- Covox: 0177200/0177202 — 16 бит влево/вправо, 0177204 — в оба, 0177206 — 8 бит
  (слово — стерео, байт — моно), 0177212 — управление (разряд 1 глушит легаси-Covox
  на 0177714).
- DMA 0177160–0177170: PCM 16 бит моно, IMA ADPCM моно и стерео, 44100 Гц, однократно
  (разряд 3 «готово») и по кругу (разряд 4 — держать состояние ADPCM). Отсчёты
  считаются от тактов ЦП, без потока (у GID — отдельный поток).
- Covox и DMA идут в микшер отдельным каналом со своим DC-блокером.

## Контроллер (0177220–0177226)

Семантика — по разбору прошивки 00019 (`RE_ARM/decompiled/src/io11.c`, `disk.c`,
`anyfile.c`, `time.c`, `screenshot.c`), а не по GID: у регистров автоматы чтения и
записи, данные ходят потоками по явным командам (015/016 — блок, 022/023 — общий
буфер, 032/033 — время, 041, 051/054, 057), DR вне потока — результат последней долгой
команды, ошибка — разряд 15 CSR, чтение за концом потока — тоже. Пока поток записи
открыт, слова DR идут в буфер, поэтому номер блока задают до 016 — так у прошивки.
Долгие команды выполняются мгновенно; по их окончании при IE в записанном CSR —
прерывание по вектору 0174.

| Команды | Что делают |
| --- | --- |
| 000, 001, 002/012, 005/006, 007/017 | сброс, выбор диска (сразу), номер блока, чтение/запись блока, размер |
| 011, 003/013, 004/014 | таблица дисков (32 × 198 слов), каталог карты, (раз)монтирование `Dnn=путь` |
| 020, 027 | маска ошибок загрузки; версия `0x1904` (прошивка 19, плата 4), затем `0x1F` |
| 021–024 | EEPROM 510 байт: чтение кладёт их за словом результата, запись берёт буфер с начала |
| 031/042, 032, 033/034 | время (14 слов: RT-11, тики 50/60 Гц, FAT, раздельно), установка — смещением от хоста |
| 037 | перезапуск платы и машины (на границе кадра) |
| 044, 047, 050–057 | снимок экрана `.SCR`, файл в память AZ, файлы карты (без «..»), размер карты |
| 010, 025/026, 035/036, 040/041/043, 042 | сеть — раздел «Сеть» |

BOOT1/BOOT2 (0177224/0177226) — потоки команд загрузчика: процессор исполняет код прямо
из регистров (`MTPS -(PC)`, `MOV -(PC),(R0)+`…); программа — встроенный bootB прошивки
(144 слова с 010000) или `[ALTBOOT]`.

## Сеть

Сетевая карта платы — ENC28J60 на SPI микроконтроллера; весь стек TCP/IP живёт в прошивке
МК («GADO-5 TCP/IP v2.00.0» MAXIOL). Он перенесён один в один с разбора прошивки 00019
(`RE_ARM/decompiled/src/net.c`, `eth.c`, `tcp.c`, `netsvc.c`, `landisk.c`, `hof.c`, `http.c`,
`time.c` и декомпилят Ghidra там, где разбор неточен): `src/core/AzNet.cpp` (ENC28J60,
ARP/IP/ICMP/UDP, DHCP, DNS, NTP, TCP), `AzNetApps.cpp` (landisk, HOF, HTTP), `AzCrypto.cpp`
(AES-256 ECB и base64 облака), `NetPort.cpp` (кабель — интерфейс хоста), `McuFiber.cpp`.

**Кабель.** Плата выходит в сеть хоста отдельным под-интерфейсом:

| `--az-net` | Что это |
| --- | --- |
| `macvtap:ИМЯ` | macvtap на физической карте хоста: у платы свой MAC в локальной сети, адрес — от DHCP этой сети, как у настоящей. Кадры к плате ядро пропускает только на MAC интерфейса — он должен совпадать с MAC платы (при расхождении — предупреждение с командой; признак — плата раз в секунду повторяет запросы DNS, а ответы до неё не доходят) |
| `/dev/tapN` | то же устройство macvtap напрямую |
| `tap:ИМЯ` | постоянный tap-интерфейс — дальше мост или NAT вручную |
| пусто / `-` | кабель вынут: линка нет, кадры уходят в никуда |

Интерфейс создаётся один раз через sudo и отдаётся пользователю — эмулятору права не
нужны: `tools/azbk-net.sh macvtap enp3s0` (имя `azbk0`, MAC — из `AZ.INI`) или
`tools/azbk-net.sh tap`. Хост сам до платы через macvtap не достучится (так устроен
macvlan) — для этого нужен второй macvlan на той же карте или tap с мостом. Кабель в GUI
и через `bk_reset {az_net}` вставляется на ходу, без перезапуска; сеть есть только на Linux.

**Настройки** — как у прошивки: `[NETWORK]` в `AZ.INI` (`DHCP=ON|OFF`, `IP`, `MASK`, `GW`,
`NTP`, `DNS1`, `DNS2`, `MAC` — 12 шестнадцатеричных цифр, `DHCPNAME`, `TIMEZONE` в минутах;
строки приводятся к заглавным, ключ ищется подстрокой). Без `MAC=` — MAC прошивки
`00:0E:35:22:0B:01`; в шаблоне `roms/azbk` — `02:0E:35:22:0B:01` (локально назначаемый,
чтобы не совпасть с живой платой в той же сети) и DHCP. Их меняет Setup платы (КТ на
экране BIOS → вкладка Network: DHCP, адрес, маска, шлюз, DNS, NTP, MAC, имя; АР2+0 —
сохранить): Setup пишет `AZ.INI` (в каталог записи карты, см. «Карта SD»), МК перечитывает
его при перезапуске. UID кристалла STM32 (ключ HOF, описание платы для landisk) у
эмулятора берётся из MAC.

**Время МК.** Счётчики прошивки (uptime: аренда DHCP, повторы TCP, опрос NTP, проверка
линка раз в 5 с) идут от TIM6, а он тикает, только пока его включила прошивка: от пуска МК
до команды 000, на время сетевых операций и ожидания по команде 010. Это эмулированное
время, от тактов БК. Код прошивки, который крутит `net_poll` в цикле, исполняется
сопрограммой МК (`McuFiber`) строго по очереди с эмуляцией: проход `net_poll` стоит 12 мкс
(опрос EPKTCNT по SPI), приём и передача кадра — по числу байт по SPI, кадр на линии —
10 Мбит/с, сброс ENC28J60 — 201 мс. Таймауты, считанные в проходах (landisk — 300000,
HOF — 20000), так же переводятся во время. Поэтому в безголовом режиме и MCP, где
эмуляция идёт быстрее реального времени, сеть «видит» таймауты короче: облако HOF может не
успеть ответить. В GUI время реальное.

**Когда сеть работает.** Как у платы: МК обслуживает сеть, только когда БК её ждёт —
команда 010 с IE (BIOS и Setup пишут `0110` в CSR перед каждым ожиданием: «крути сеть,
пока я жду»), один проход после каждого чтения и записи блока, сетевые команды и пуск.
Пока БК занята своим (Setup на БК-0011М перерисовывает экран секунд девять), на ping и HTTP
никто не отвечает, кадры копятся в кольце приёма ENC28J60 (6,6 Кбайт; семь и больше —
прошивка выбрасывает все). Ожидание по 010 кончается любым обращением БК к регистрам
контроллера — чтением или записью CSR и DR (кроме записи той же 010 с IE), и обращение тут
же обслуживается, без прерывания: драйвер AZ337 ставит `0110` после каждой операции, а
следующую начинает с записи номера блока в DR; игры начинают с `TSTB @#177220`. Пока идёт
другая сетевая задача МК (landisk, HOF), CSR читается нулём («не готов»), DR — нулём;
запись в CSR защёлкивается и исполняется по окончании задачи; по окончании при IE —
прерывание по 0174.

| Команда | Что делает |
| --- | --- |
| 010 | с IE — крутить `net_poll`, пока БК не запишет CSR; без IE — один проход |
| 040 / 041 | IP, маска, шлюз, NTP, DNS1, DNS2 — 12 слов (адреса в порядке байтов сети) |
| 043 / 041 | MAC — в первые 3 слова того же буфера |
| 042 / 032 | запись времени по часам NTP (`ntp_offset + uptime + TIMEZONE`); до ответа NTP — 1970 год |
| 035 | опросить NTP сейчас; 036 — RTC по часам NTP (если год позже 2021) |
| 025 / 026 | облако HOF: сессия (`/init/<MAC>/<UID>`) и запрос (`/work2/<SID>/<base64(AES)>`) — JSON в общем буфере |
| 004 / 014, 005 / 006 | сетевой диск landisk (`Dnn=` с первой буквой N, P, R, S, A): OPEN/CLOSE, чтение и запись блока |

Службы и их особенности (все — как в прошивке):

- **DHCP**: DISCOVER раз в 15 с без адреса; в REQUEST — имя из `DHCPNAME` (опция 12),
  список опций `{1,3,42,54,6,73}`; аренда и T1 урезаются до 6 ч; продление — одноадресно в
  T1. xid — из миллисекунд и хвоста MAC прошивки по умолчанию.
- **Постоянный адрес** (`DHCP=OFF`): потеря линка (проверка раз в 5 с) обнуляет адрес до
  перезапуска МК — так в декомпиляте `enc_link_monitor` (DNS остаются). Без кабеля, значит,
  адреса нет уже в BIOS: первая проверка — через секунду после пуска МК. Сброс ENC28J60 защёлку PHSTAT1.LLSTAT не роняет (иначе прошивка переинициализировала
  бы чип раз в 5 с бесконечно).
- **ARP** — кэш на 16 записей, запрос не чаще раза в 200 мс (и он затирает кадр, который не
  ушёл); **ICMP** — ответ на ping с поправкой суммы без переноса; **DNS** — 4 имени
  (`back.hof`, `back2.hof`, `landisk`, `landisk2.maxiol.com`), повтор раз в секунду, пока не
  ответят; **NTP** — запрос с порта 14444, первый байт 8, раз в 10 минут.
- **TCP** — 10 соединений, 10 служб, «послал — жди подтверждения», повтор раз в секунду до
  5 раз, MSS 1024.
- **HTTP** на порту 80 («MAXIOL HTTP/WEBDAV Server v1.00»): GET файла карты (сначала каталог
  записи, потом сама карта), HEAD, OPTIONS, `/CMD.SCREENSHOT` (снимок `.SCR`),
  `/CMD.REBOOT` (перезапуск через 3 с). GET каталога пишет на карту `INDEX.HTM` с
  оглавлением, а сам отвечает 404 — оглавление берут запросом `…/INDEX.HTM`. Тип содержимого
  у файлов не ставится (ошибка поиска MIME в прошивке).
- **landisk** — `landisk.maxiol.com:34162`, запрос 938 байт, ответ 516, CRC-16/MODBUS.
  Сетевые диски из `[DISKS]` открываются при пуске МК: до 10 с ждать адреса, `landisk_init`
  (DNS, ARP, ping), OPEN — всё это время БК в сбросе (`bk_reset_hold` прошивки).
- **HOF** — `back.hof.maxiol.com:80`, ключ AES-256 `%08X%08X%08X_HOF2025` из UID, ответ
  `/work2` меняет ключ; при сбое — `{"RESULT":"ERROR","DESCRIPTION":"CONNECTION_ERROR"}`.

Снимок состояния хранит настройки, часы NTP, аренду DHCP и ключ HOF (метка `NET1` в конце
хвоста AZB1); соединений TCP и незаконченной задачи МК после загрузки нет. Сводка —
`bk_io_state` (адреса, состояние DHCP, счётчики кадров, соединения TCP).

**Проверка без root.** В пространстве имён пользователя tap создаётся без прав, и на другом
конце работает настоящий стек ядра:

```sh
unshare -rn sh -c 'ip link set lo up; ip tuntap add tap0 mode tap; ip link set tap0 up;
  ip addr add 10.0.0.1/24 dev tap0;
  dnsmasq --interface=tap0 --bind-interfaces --dhcp-range=10.0.0.50,10.0.0.99,1h \
          --dhcp-option=42,10.0.0.1 --address=/landisk.maxiol.com/10.0.0.1 --no-resolv;
  ./build/bk0010-emulator --az --az-net tap:tap0'
```

Эмуляция должна идти в реальном времени (GUI): безголовый режим проходит BIOS быстрее,
чем dnsmasq выдаёт адрес (перед OFFER он ещё около 3 с проверяет адрес ping'ом; `--no-ping`
это убирает). Учтите и каталог записи карты: `AZ.INI`, сохранённый Setup, главнее шаблона
`roms/azbk` — если там `DHCP=OFF` без адреса, сети нет, пока её не включить в Setup.

Так проверено: DHCP с `dnsmasq` (в BIOS — адрес, NTP, MAC и «Lan Date» по NTP), ping,
HTTP (GET/HEAD/OPTIONS, файл 300 Кбайт байт в байт), постоянный адрес из Setup, загрузка
ANDOS 3.30 с сетевого диска (поддельный сервер landisk на Python) и сессия и запрос HOF с
сервером, у которого своя реализация AES (`cryptography` Python).
