# Запись видео с экрана

Экран эмулятора пишется в файл **AVI**: один кадр видео — один кадр БК. Частота
кадров поэтому точно та же, что у машины, и записывается в файл точной дробью:

| Машина | Такт ЦП | Тактов в кадре | Частота кадров |
| --- | --- | --- | --- |
| БК-0010-01 | 3 000 000 Гц | 61 440 | 48,828125 Гц |
| БК-0011М | 4 000 000 Гц | 81 920 | 48,828125 Гц |

В заголовке AVI `dwRate/dwScale = 3125/64`, `dwMicroSecPerFrame = 20480`
(ffprobe показывает `r_frame_rate=3125/64`). Время в файле — **эмулируемое**: пока
эмуляция стоит (пауза, отладчик), кадров нет, а если хост не успевает за реальным
временем, видео всё равно идёт с частотой БК.

## Как включить

* **GUI:** меню «Видео» → «Записывать видео…» (`Ctrl+F5`) — спросит имя файла (по
  умолчанию `bk_ГГГГММДД_ЧЧММСС.avi` в папке прошлой записи); повторное нажатие или
  выход из эмулятора останавливает запись. Пока идёт запись, справа в строке состояния
  — `● ЗАПИСЬ мм:сс`.
* **Командная строка:** `--video файл.avi` — запись с первого кадра:
  ```sh
  ./build/bk0010-emulator --video demo.avi demo.bin                 # GUI: до остановки/выхода
  QT_QPA_PLATFORM=offscreen ./build/bk0010-emulator --frames 3000 --video demo.avi demo.img
  ```
  В безголовом режиме в видео попадают все `--frames` кадров основного прогона (после
  загрузки монитора и образа). `Ctrl+C` в терминале закрывает окно как обычно, и файл
  дописывается целиком.

## Настройки

Меню «Видео» → «Кодек» и «Кадр видео» (запоминаются, действуют со следующей записи);
`--video-codec` и `--video-size` перекрывают их на один запуск. Безголовый режим
настроек GUI не читает: там кодек ZMBV и кадр 1024×768, если ключи не заданы.

* **Кодек:** пока один — **ZMBV**.
* **Кадр:**
  * `1024x768` (по умолчанию) — точка буфера БК блоком 2×3, то есть пиксель
    цветного режима — 4×3, как в окне с включёнными пикселями 3:4 (`F11`);
  * `512x256` — как буфер экрана, без масштабирования; в файл пишется блок OpenDML
    `vprp` с соотношением сторон 4:3, и ffmpeg/mpv показывают его правильно
    (`sample_aspect_ratio=2:3`). Проигрыватели, которые `vprp` не читают, покажут
    картинку сплюснутой.

## Кодек ZMBV

**ZMBV** (Zip Motion Blocks Video, FourCC `ZMBV`) — кодек записи экрана DOSBox, без
потерь. Кадр режется на блоки 16×16; для каждого ищется сдвиг относительно прошлого
кадра (векторы до ±10 точек, сначала ближние), и пишется XOR с ним — или ничего, если
блок не изменился. Всё сжимается **одним потоком deflate**, который сбрасывается
только на опорных кадрах, поэтому статичный экран почти ничего не стоит. Опорный кадр
— первый в файле и далее каждые 300 (≈6 с).

Цветов у БК на кадр — единицы, поэтому формат **8 бит на точку с палитрой**. Палитра
набирается по мере появления цветов: опорный кадр несёт её целиком, промежуточный —
изменение (XOR) с флагом DeltaPalette. Индекс 0 — чёрный: им же декодер считает точки
за краем кадра, на которые может указывать вектор.

Файлы читают ffmpeg (`zmbv`) и всё, что на нём построено (mpv, VLC); в Windows — кодек VfW из DOSBox.
Перекодировать: `ffmpeg -i demo.avi -c:v libx264 -crf 18 -pix_fmt yuv420p demo.mp4`
(для 512×256 добавьте `-vf scale=1024:768:flags=neighbor`).

Объёмы для ориентира (1024×768): неподвижный экран — десятки байт на кадр; INSULT —
~0,9 Мбайт/мин; «Bad Apple» — ~2,2 Мбайт/мин. Кодирование идёт в отдельном потоке,
~3 мс на кадр при сплошном движении (кадр БК — 20,48 мс).

## Устройство

* `src/core/AviWriter` — AVI 1.0: `hdrl` (`avih`, `strh`, `strf` с BITMAPINFOHEADER,
  `vprp`), кадры `00dc` в `movi`, индекс `idx1`; счётчики и размеры дописываются при
  закрытии. Файл больше ~1 Гбайт (предел AVI 1.0 без OpenDML) продолжается в
  `имя_002.avi`, `имя_003.avi`… с опорного кадра.
* `src/core/Zmbv` — интерфейс `VideoEncoder` и кодировщик ZMBV; список кодеков —
  `videoCodecs()`, фабрика — `makeVideoEncoder()`. Новый кодек — ещё один `VideoEncoder`.
* `src/core/VideoCapture` — очередь кадров (до 16; если кодировщик не успевает, эмуляция
  ждёт, кадры не теряются), поток кодирования, масштабирование, деление на файлы.
* GUI отдаёт кадр, только если последний слайс кадра действительно выполнился
  (`MainWindow::frameDone_`): отладчик и пауза в видео ничего не добавляют.

## Проверено

* ffprobe: `zmbv (ZMBV), pal8, 1024x768, 48.83 fps`, `r_frame_rate=3125/64`, число
  кадров совпадает с `--frames`; в режиме 512×256 — `display_aspect_ratio=4:3`.
* Последний кадр, декодированный ffmpeg, попиксельно совпадает со снимком `--shot` того
  же прогона (INSULT, 1500 кадров).
* GUI под Xvfb: запись с `--video`, остановка по сигналу — файл цел (345 кадров за 7 с).
* `cpu_tests`: свой декодер ZMBV — 20 кадров туда и обратно без потерь (неполные
  краевые блоки, смена палитры, опорные кадры по интервалу), сдвиг кодируется векторами;
  AVI — 3125/64, 20480 мкс, счётчики и `idx1`, продолжение в `_002.avi` без потери кадров.

## Чего нет

* Звука в видео (дорожки PCM). Звук эмулятора можно записать отдельно — MCP `bk_audio`.
* Записи из MCP-сервера.
* Других кодеков.
